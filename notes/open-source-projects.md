# 3 个 AI 开源项目对比

> 记录日期：2026-11-09

## 1. DeepSeek-R1

- **一句话**：深度求索开源的推理大模型，671B 总参数 / 37B 激活，128K 上下文，主打数学、代码和逻辑推理
- **主要语言**：无代码（纯文档仓库，只有 README + 论文 PDF，权重在 HuggingFace）
- **Star 数**：92.0k
- **Fork 数**：11.7k
- **安装方式**：无安装步骤。模型权重在 HuggingFace 下载，本地部署需要配合 vLLM / SGLang 等推理框架；日常使用直接调 API 即可
- **我关注的点**：671B 总参数只激活 37B，这是 MoE（混合专家）架构的特点，每次推理只用一小部分参数，成本和速度都降下来。这个数字对比是面试聊模型架构时最容易出彩的点

## 2. LangChain

- **一句话**：构建 AI Agent 和大模型应用的框架，把可复用组件和第三方集成串起来，简化 AI 应用开发
- **主要语言**：Python 99.5%
- **Star 数**：149.2k
- **Fork 数**：25.1k
- **安装方式**：`uv add langchain`（新版推荐 uv 包管理器，传统 `pip install langchain` 同样可用）
- **被依赖数**：290K 个仓库使用
- **我关注的点**：第 4 周做 RAG 项目会用它串起「加载 → 切分 → 向量化 → 检索 → 生成」。它的 Integrations 能直接接各种向量库和模型，换模型不用改业务代码

## 3. NextChat

- **一句话**：轻量快速的 AI 聊天助手，支持 Claude、DeepSeek、GPT-4、Gemini 等 100+ 模型，网页、桌面、手机多端可用
- **主要语言**：TypeScript 91.9%（另有 SCSS 6.7%）
- **Star 数**：88.9k
- **Fork 数**：58.6k
- **安装方式**：三种
  1. 一键部署到 Vercel（README 的 Get Started 只有三步：拿 API Key → 点 Deploy → 访问）
  2. 下载约 5MB 的桌面客户端（Win/Mac/Linux）
  3. 仓库含 Dockerfile 和 docker-compose.yml，可自行 Docker 部署
- **我关注的点**：第 3 周做的聊天界面可以参考它的样子——流式输出、多轮对话、Markdown 渲染、深色模式

## 我的观察

### 1. 「安装方式」的含义因项目类型而变

| 项目类型 | 安装方式长什么样 | 例子 |
| --- | --- | --- |
| Python 库 | 一条命令 `uv add xxx` | LangChain |
| 前端应用 | 一键部署到云端，本地不用装 | NextChat |
| 模型 | 没有安装，下载权重 + 推理框架 | DeepSeek-R1 |

**结论**：读 README 时先判断项目是「库」「应用」还是「模型」，才知道该找什么。

### 2. Star 数不等于质量，要看生态数据

| 项目 | Star | Fork | Fork/Star 比 | 说明 |
| --- | --- | --- | --- | --- |
| DeepSeek-R1 | 92.0k | 11.7k | 13% | 关注度高，但仓库只是文档 |
| LangChain | 149.2k | 25.1k | 17% | 被 290K 仓库依赖，生态最广 |
| NextChat | 88.9k | 58.6k | **66%** | Fork 比例极高，说明很多人真的部署了自己用 |

**结论**：Fork 比例高说明「想自己用」，Star 高但 Fork 低说明「只是觉得不错」。NextChat 的 66% 很能说明它是拿来即用的工具型项目。

### 3. 语言占比反映项目性质

- Python 99.5% → 纯后端库（LangChain）
- TypeScript 91.9% + SCSS 6.7% → 前端应用（NextChat）
- 无语言标识 → 纯文档仓库（DeepSeek-R1）

**结论**：About 栏的语言彩色条能一眼看出项目是前端、后端还是文档。

### 4. 头部项目都有多语言 README

NextChat 仓库里有 `README.md`、`README_CN.md`、`README_JA.md`、`README_KO.md`——英、中、日、韩四种语言。

**结论**：README 有多语言版本，说明项目用户群是国际化的，也说明维护者投入成本高。

### 5. 三个项目都是 MIT 许可证

MIT 是最宽松的开源协议：可以商用、可以修改、可以闭源分发，只要保留版权声明。

**结论**：看到 MIT 就知道「拿来改、拿来卖都没问题」，面试聊开源合规时这是基本常识。
